Offline database implementation

PROVIDED

Electron uses local SQLite with WAL mode, repository-based data access, and transaction-backed invoice/payment/stock updates. A restart test verifies a bill and inventory change remain stored and transaction sync work can be re-queued after restart. Tests do not exercise every machine failure or restore scenario.

  • SQLite connection
  • SQLite schema
  • Repositories
  • Persistence test
7

Synchronization mechanism

PARTIAL

Local changes are queued, pushed when connectivity is available, retried after failures, and deduplicated by the server. Product/category/customer conflict resolution uses server-side last-write-wins snapshots; invoice/payment/stock changes use transaction events. The desktop client does not pull cloud changes into local SQLite, so multi-device bidirectional sync is incomplete.

  • Sync engine
  • Cloud client
  • Sync API
  • Conflict policy
